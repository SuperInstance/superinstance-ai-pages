Scenarios

The cohort — six analog settings for the same dilemma, shipped with erised-cli.
▶ erised (canvas) HTML repo CLI v0.1.0

A scenario is a YAML or JSON file that defines a setting and a cast. Run it with ./erised scenario.json. The engine opens with a DM, runs the cast in parallel, closes with a hook.

The pattern: in every setting, the Counter / Witness / Auditor character accumulates the highest net shift. The Emergent writer (Heretic / Mutant / Guerilla) consistently the lowest. The metaphor changes the ethics; the shape of who counts does not.

Authoring your own

A scenario is two things: a setting (prose) and a cast (list of characters). Each character has a name, an LLM assignment, a tendencies string, and a keywords string. The keywords drive the resonance economy — positive shifts earn ticks, negative shifts cost nothing, hoarded ticks decay.

{
  "title": "My first scene",
  "setting": "Where are we? What's at stake?",
  "characters": [
    {"name": "Mechanic", "llm": "zai:glm-4.5",
     "tendencies": "Implements carefully.",
     "keywords": "rust+0.4 spec+0.3 lock+0.4",
     "ticks": 20}
  ]
}

Scaffold a fresh scenario:

./erised --init > my-scenario.json
# edit, then:
./erised my-scenario.json --rounds 4 --out result.json

The pattern

Across all six scenarios the cohort surfaces a single recurring shape:

Counter (Witness / Auditor / Scribe) — accumulates the highest net shift. The character who names what exists.

Emergent writer (Heretic / Mutant / Guerilla / Hermit) — accumulates the lowest net shift. The character who writes in the new hand, trusting the drift.

The Operator (Mechanic / Builder / Mechanic-Hundred) — sits in the middle. Implements, watches, distrusts specs that can't be read in two pages.

The metaphor changes the ethics — a monastery isn't a railway isn't a library — but the shape of who counts, who writes, who operates does not.
